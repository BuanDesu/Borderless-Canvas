# 触控板接收层的命中修正

2026-10-25。用户确认输入来自本机笔记本触控板。前两轮的队列分派和精度检查通过后，实际两指滚动仍无反应；不能据此把实体设备标记为通过。

## 可复现缺陷

新的原生滚动接收层使用 `STATIC` 窗口类，但没有设置 `SS_NOTIFY`。该类默认的 `WM_NCHITTEST` 返回 `HTTRANSPARENT`，系统命中测试会跳过接收层。这与旧版可正常工作的 WinForms 接触表面不同。先前同步和异步消息夹具直接指定 HWND，绕过了命中测试，因此没有覆盖这个错误。

新增隐藏原生检查先复现失败：接收状态返回穿透。修正窗口过程后，接收状态明确返回 `HTCLIENT`，按钮透明期间返回 `HTTRANSPARENT`，释放后恢复接收。依据是微软的 [Static Control Default Message Processing](https://learn.microsoft.com/en-us/windows/win32/controls/about-static-controls)。

## 输入与焦点

接收层保留约 2.4% 不透明度，并恢复旧版表面的可聚焦能力；进入模式时在面板隐藏后请求接收焦点。实际点击仍在低级钩子中先解除命中，再交给下方应用；不捕获左键拖动，不重放应用点击。桌面右键后来改为核验后的成对交接，见[当前机制](touch-context-handoff.md#桌面成对交接)。按钮按住、系统菜单或弹出层期间不重新接收。

后续取消了桌面移入时自动请求焦点，只在进入或点击工具条标题时请求接收。退出时仅在接收层仍拥有前台的情况下尝试返回经过身份核验的原应用，用户已经选中的其他应用保留焦点。工具条外观和总览/退出两键保持紧凑。

输入状态区分钩子看见与实际接管的数量、纵横轴和拒绝原因。接收层区域匹配与命中状态为匿名布尔值，不记录窗口身份、真实标题或输入轨迹。

## 实体设备证据与范围

隔离入口 `--touchpad-lab` 在主面板、自动接管和恢复流程之前分支，只移动自身测试网格，不登记或移动桌面应用。可选 `--lab-report` 将匿名计数写到指定本地文件；报告、截图和进程信息不提交到仓库。

清理重复实验进程并由用户暂停正式画布后，用户亲自确认 `touchpad-hit-r2` 网格可随双指移动。该次记录到纵向 116、横向 90 个消息，形成 70 次相机更新；均经生产输入钩子进入，没有同时落入下方测试页面。它证明此设备的物理输入接收已打通，尚不代替正式画布内真实窗口、应用点击/双指右键以及多屏的验收。

Release 全量回归通过：332 项模型、24 项文件、103 项原生检查，以及 UI 和完整原生总览检查，构建无警告或错误。新增命中检查与原有两轴队列、透明按钮周期和暂停销毁检查一起进入默认 CI。完整兼容、性能与发布矩阵仍由 T11–T13 追踪。

后续核对并直接启动正式构建 `2c212b3` 后，用户确认真实画布可以移动，但桌面双指轻点右键需要多次、触控条仍在。两轴接收与菜单交接分开验收，后者见[右键交接修正](touch-context-handoff.md)。

用户随后复验准确构建 `b02cd13`，反馈体验良好、此前问题不再出现；正式画布双轴、桌面单次右键及菜单/应用点击后的连续滚动据此完成本机触控板验收，见[准确产物与验证范围](touch-context-handoff.md#实体复验与交付)。
