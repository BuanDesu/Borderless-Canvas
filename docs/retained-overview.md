# 保留空间关系的总览渲染重构

跟踪 [Issue #41](https://github.com/BuanDesu/Borderless-Flat-Window/issues/41)。用户确认主面板方向通过，总览可以即时反向，但仍有顿挫；选窗后重新进入时快速 Tab 返回也有问题。用户已选择保留空间关系，重做渲染层。

## 原生任务视图的边界

Windows 自带任务视图可以用于原生选窗。微软公开的 [IVirtualDesktopManager](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ivirtualdesktopmanager) 只提供查询窗口所属桌面、判断当前桌面和移动窗口到桌面的方法，没有嵌入任务视图、自定义其窗口坐标、缩略图动画或工作区卡片的方法。因此，依据目前公开文档，不能把系统任务视图当作可定制的无限画布渲染控件。

[Shell.WindowSwitcher](https://learn.microsoft.com/en-us/windows/win32/shell/ishelldispatch5-windowswitcher) 的公开契约仍描述 Vista 的 3D 窗口堆叠，且没有布局参数；不能据此承诺在所有 Windows 版本上得到可定制任务视图。直接使用系统选窗器会失去本项目按世界坐标布置地图及保存视角的语义。用户没有选择这一取舍。

可以继续使用 Windows 的图形基础能力，但不能把这些能力称为“嵌入原生任务视图”。[DWM 缩略图](https://learn.microsoft.com/en-us/windows/win32/dwm/thumbnail-ovw) 是源窗口到目标窗口的动态二维关系；它不提供可任意挂入 WPF 视觉树的窗口纹理或任务视图动画。当前版本保留 DWM 内容关系，以 WPF 视觉树承载地图和动效，不使用 Explorer 注入、未公开 Shell 接口或系统文件修改。

## 新的运行路径

- `SpatialOverviewScene` 用一个 WPF 宿主承载地图、搜索和工作区。运行时不再创建旧的 WinForms 地图及工作区控件树；旧树仅用于原有合成验证，不是运行时备用总览。
- 地图卡片保留统一投影、真实相对位置、标题筛选和空间选择。DWM 继续负责真实窗口内容及工作区视窗的裁剪，卡片提供可访问的 Invoke 操作。
- 原始桌面只作为进入/返回的短期图像；已缓存的本地壁纸图集按主屏区域裁切，作为总览毛玻璃背景。工作区仍使用整个桌面工作区图集，并按各视角绘制真实窗口内容；不会留下大块旧应用背景作为总览底色。
- 模糊使用现代 WPF `BlurEffect`，在有硬件能力时缓存；不使用旧 `BitmapEffect`。运行时不再进行整屏 CPU 模糊或整页 `DrawToBitmap`。初次 WPF 控件初始化移到管理器启动阶段预热，成本仍需记录，不假装已经消失。
- 原生预览注册等到场景布局稳定后进行，避免在零尺寸或中间布局阶段重复创建关系。
- 未遮挡的焦点图像直接使用缩放/平移 RenderTransform 动画；其余预览保持静态地图坐标，仅调整透明度，避免在界面线程逐帧搬动原生缩略图。取消可从当前进度反向；确认窗口或工作区后立即交接，不再等待不可反向的旧返回动画。
- 关闭客户区动画、关闭外观动画或无硬件渲染能力时直接切换。原生窗口比例、世界位置、画布导航和恢复日志保持原有规则。

## 输入生命周期

每次请求都有递增的输入会话编号。显示、激活和关闭回调只更新对应会话；晚到的旧回调不能关闭新会话，也不能重绑定新宿主。显示通知不再等同于激活完成；真实 Activated 通知或观察到宿主位于前台后才结束准备期。之后应用和模态框中的 Tab 继续交给原控件。

结束旧总览时，在焦点交接和 COM 查询前释放旧宿主；重入产生的新请求有独立编号。暂停画布也会清理待打开的输入状态。以上有纯模型和专用输入线程检查，不把合成动画的反向测试当作真实物理连按已经验收。

## 资源与隐私

每个总览使用自己的预览关系、静态逐帧订阅和图像。关闭时停止时钟、解除订阅并清除图像源、效果及 DWM 资源。没有后台录屏、图像上传或抓取其他应用的编辑输入。

仅明确标记为 synthetic 的场景允许导出测试图片；生产场景的导出方法直接拒绝。桌面和壁纸图像只在内存使用。可选计时仅包含渲染器类别、尺寸、数量和耗时，不包含窗口标题、身份、文件来源或像素。试用包不包含本机状态。

## 验证与测量

`scripts/check.ps1 -SmokeUi` 除原有界面验证外，运行 `--scene-check`，覆盖生产窗体的搜索/确认/关闭/重开/Tab 取消，以及 1920×1080、3440×1440、960×720 下的场景布局、无匹配降级、搜索不重排、空工作区、边缘裁剪、两次中途反向和释放。测试只使用合成像素，不捕获桌面；首次布局中零尺寸滚动视窗也会执行预览布局回调，防止构造无效物理矩形。

本机较早的真实自有 Probe 样本：旧路径的背景及界面准备合计约 170–190ms；新路径样本分别约 28–38ms 和 0.5–1.4ms，整页快照为零。这两项不包含所有入口工作，也不是严格对照实验。可选计时现在补充窗口核验、场景构造和输入捕获到首个合成回调的耗时，不能只用其中某个短阶段代表总打开延迟。

新路径仍有 20–30ms 量级的回调长间隔；回调间隔不能等同于 GPU 实际呈现帧率。主观丝滑程度、快速物理连按，以及 T11/T12 的多窗口、硬件和长期兼容矩阵保持待验收。此前发现的文件替换偶发访问失败也没有因为本轮单次通过而宣称解决。

加入完整入口计时后的自有 Probe 样本曾记录输入到首回调约 273ms，说明短的局部阶段不能代表整条入口已经合格；该样本还受桌面自动化观察影响，需以独立负载验证和用户自然操作继续测量。普通节奏的真实搜索、预览恢复、卡片选窗、再次打开与 Tab 返回已有实测，未据此声称物理快速连按通过。

最终提交、完整检查、CI、合并、包哈希及后续真实测量回填 Issue；该记录与用户体验验收分开。

后续已补充[独立原生负载夹具与入口阶段拆分](overview-load-baseline.md)，发现并降低多窗口注册时重复创建 COM 查询服务的成本；单窗等待与实际呈现仍未据此宣称解决。
