# 工作区窗口布局

从 `0.1.0-preview.6` 起，空间总览的工作区可以保存窗口成员与布局，并复用已有窗口或按需启动缺失的受支持本地软件。旧位置书签继续兼容。

## 使用

1. 开始画布，把需要保存的软件窗口放到当前视区，打开空间总览，点击工作区区域的“+”。“保存窗口布局”会显示本次成员数量，确认后写入本地。
2. 点击卡片“打开并复原”。软件窗口仍在时优先复用，缺失的受支持软件按保存的启动项启动，窗口就绪后恢复位置和尺寸。进度窗口给出每项结果，可以取消。
3. 右击卡片 → “更新布局（当前视区）”明确替换快照；关闭窗口、暂停画布或退出软件不会自动更新、清空或删除已保存成员。
4. 右击 → “查看成员 / 启动项”，可移除不需要的成员、开关自动启动、调整完整 EXE 路径与独立参数。每行是一个原样传递的参数，不是 shell 命令。多个同程序窗口不明确时，先在这里明确选择当前窗口，再打开工作区。明确选择仅在当前管理器会话有效；所选窗口消失后会要求重新选择，不回退到其他窗口或启动替代实例，重启后需重新确认多文档选择。
5. 重命名保留工作区 ID；删除只删快照，不关闭软件。旧工作区显示“仅位置”，仍跳转到原坐标；可用“更新布局”升级为窗口快照。

保存默认包含当前各屏实际工作区内有正面积交集的普通画布窗口，部分相交也包含。固定便签、最小化/隐藏窗口和屏幕之间空洞里的窗口不加入新快照；已保存成员之后被最小化不会丢失，复原会先还原它。单个快照最多 64 个成员。窗口仍在同一共享画布上，切工作区不隐藏、不杀掉其他软件。

位置采用现有世界坐标，相机坐标仍是工作区地址。恢复尺寸与相对相机的偏移按当前/保存 DPI 比例换算；原位置完全不在当前实际屏幕工作区时，目标放到主屏可用区域附近。混合或未知 DPI 继续受现有画布支持范围限制，显示变化在安全边界取消操作并暂停核验。

## 匹配与支持范围

- 同一管理器会话可用目录窗口 ID 复用确切实例；它只在该会话有效，不是 HWND/PID 的替代持久身份。跨会话以从系统核验的完整程序路径、窗口类/框架类族和唯一性保守匹配，不按标题或进程名称猜测文档。
- 普通桌面 EXE 的默认启动项仅含程序路径，不采集完整进程命令行。结构化参数使用 `ProcessStartInfo.ArgumentList`，`UseShellExecute=false`。路径、窗口标题与参数只保存在用户本地数据中。
- 多个同程序窗口缺少可核验的文档上下文时，不自动判断哪一个属于哪份文档，也不为了凑齐数量启动副本；在成员编辑器选择当前窗口。相同会话中的原实例可直接区分。重启后同程序多文档的全自动重建尚不支持。
- 带参数的已有窗口不被参数字符串自动证明为目标文档；需要同会话确切实例或用户明确选择。对缺失软件，参数可按软件自身支持的方式打开文档，但窗口出现不等于文档内容已经恢复。
- 系统代理、资源管理器目录、打包应用和通用文件/URL 入口没有可信启动适配时，保留成员并提示调整/手动打开；不执行从窗口标题、任意 shell 字符串或系统代理中拼出的命令。
- 启动器/单实例软件只有在最终窗口能够匹配时才确认布局；转交到不同程序、产生多个不明确窗口或不出现可管理窗口，会显示部分失败或超时，不伪造成功。
- 无法恢复任意应用的内存、未保存内容或所有浏览器标签，不承诺重建窗口叠放顺序或焦点。卸载、路径变化、权限不足、软件最小尺寸限制或拒绝移动会明确失败；不要把窗口复原等同于应用会话备份。

## 生命周期与恢复

只有用户打开工作区才会启动缺失项。没有保活进程或“关闭后自动重启”监视器。窗口就绪和布局核验的等待期限为 30 秒，在每次调度时检查；这不是启动器或系统调用的强制中断期限。启动项建议使用本地 EXE；慢网络路径和长时间不返回的启动调用的取消响应尚未验收。同一进行中的请求合并，快速切换共享最近启动保护，30 秒内不再次为同一程序发出启动。超时软件仍可能稍后出现，请先检查再重试。

恢复期间暂停导航、前台跟随和自动接入排布；就绪读取使用已有事件目录和有期限的 100ms 调度，不持续枚举桌面。无恢复任务时计时器停止，原有 250ms 输入健康检查与按需导航调度继续工作。已经提交的原生位置仍按既有 40ms 验证协议核验，成功必须观察到目标布局。

取消/切换停止后续启动与提交，已经启动的软件保持打开。已完成的窗口可以留在复原布局；已登记但尚未接入的最小化窗口会恢复原始状态。提交期间重入取消/退出会停止旧代际并走恢复协议。暂停或退出管理器恢复接管前的位置、尺寸和显示状态；失败保留恢复记录，交恢复中心处理，不绕过日志直接操作目标 HWND。

原生实现使用非激活异步显示/移动，并在每次操作前核验恢复所有权。相关平台语义见 Microsoft 的 [ShowWindowAsync](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindowasync) 与 [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos) 文档。

## 数据与兼容

沿用本地 `bookmarks.json`，格式升级为版本 2，保留原 ID、名称、相机坐标并增加可选布局。版本 1 读取不改写文件、不推断历史成员；明确编辑保存时才原子写入版本 2。窗口成员保存随机成员 ID、会话范围的目录 ID、程序描述、窗口类和世界矩形，不保存旧 HWND/PID。

继续使用独占租约、16 MiB 上限、整份校验、外部变更检测和同目录原子替换。损坏/未知版本不覆盖原文件、不发布部分成员；原来的备份并新建入口保留。旧程序无法理解版本 2 时应保持只读，建议升级源码版本前备份本地数据。

## 本地验证

Core 包含快照持久性、保存失败、集合冻结、结构化参数、复用/缺失启动、重启、合并/取消、慢启动与失败、同程序歧义、最小化、句柄复用，以及正式管理会话的尺寸/恢复协议、取消重入和 DPI/屏幕变化回归。存储检查覆盖版本 1、版本 2 布局往返、损坏成员与原文件保持。

Ui 使用注入启动端口，覆盖实际控制器保存视区/部分相交/便签规则、现有窗口布局、只启动缺失合成成员、成员编辑器、取消后计时器停止、旧书签跳转和原有输入看门狗回归。

独立原生检查只使用本项目两个自有透明 A/B 测试程序，覆盖真实位置及尺寸复原且不增实例、只重启关闭的一项、两个都关闭并重建管理会话后从本地存储复原、参数原样传递，以及最小化登记/原位恢复和日志清空。不会启动生产管理器或操作用户软件：

夹具在显示前为自己的 HWND 设置便签标记，使已经运行的其他管理器不会自动接入它们；原生检查器通过显式注入端口单独管理这些已验证的自有句柄。

```powershell
./scripts/check.ps1 -Configuration Release -Layer Core
./scripts/check.ps1 -Configuration Release -Layer Ui
# 先完整构建；每次选用新的 ignored 输出目录
dotnet run --project tests/BorderlessFlatWindow.Windows.Checks -c Release --no-build -- --workspace-only artifacts/workspace-native-new
```

特定第三方软件、实际文档/浏览器上下文、真实多屏/DPI 切换、物理设备和长期运行尚需单独验收。没有将本地通过写成远端 CI 或完整兼容性通过。
