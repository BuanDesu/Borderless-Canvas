# 触控消息泵与最小化窗口

2026-10-25。用户复验触控两轴操作仍失效，并反馈最后一个窗口最小化或关闭后画布退出。本次先复现三个实际代码路径，再修正消息分派和生命周期时序。

## 标准触控板语义

两指纵向滚动使用 `WM_MOUSEWHEEL`；横向使用 `WM_MOUSEHWHEEL`，或驱动提供的 Shift+纵向滚轮。斜向操作保留两个轴的有符号小增量，在同一相机帧叠加成二维位移，不把每轴归整为一格，也不凭手指数构造鼠标拖动。双指轻点产生的完整右键按下/释放交给 Windows，不转成左右双键画布手势。系统和驱动决定具体手势映射，软件消费收到的兼容鼠标消息。

微软文档定义[水平滚轮正值向右](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-mousehwheel)，并说明[精密触控板可发出 delta=1 的滚轮消息](https://learn.microsoft.com/en-us/windows/win32/w8cookbook/windows-precision-touchpad-devices)。现有相机已经保留这种精度；这次故障主要在消息到达之前。

输入线程原先只显式分派 Raw Input，对普通 HWND 的队列消息没有调用 `DispatchMessage`。上一版隐藏接收器检查使用同步 `SendMessage`，会直接进入窗口过程，因此没有覆盖真正的异步消息泵。新增检查用 `PostMessage` 投递到隐藏接收器并等待输入线程屏障，修复前确实收不到三条两轴/Shift 消息。现为普通窗口消息补齐分派；保留钩子消费优先和现有透明按钮周期，避免重复累计。

新增异步检查进入默认 Windows CI，与隐藏接收器样式、按钮透明周期和暂停释放检查一同运行，不安装全局钩子、不显示输入层、不注入系统鼠标事件或限制光标。

## 最小化和关闭

最小化窗口通常仍为 `IsVisible=true`，先前仅检查隐藏状态，随后准入检查拒绝 `IsMinimized`，导致整组暂停。现先按可验证的原生身份局部挂起隐藏或最小化窗口，清除它的移动确认，保留恢复记录及世界位置；相机和其他窗口继续运行。恢复为普通窗口时重新按当前相机投影；用户从任务栏恢复并激活该窗时找回保存的世界位置，不把系统最小化坐标写回画布。

关闭还有一条快照竞态：目标已经销毁，但目录的销毁事件尚未消费，下一帧平移的原生校验返回“无当前持久所有权”，导致整组恢复。现原生移动批次跳过已关闭、或身份/标记仍匹配但已隐藏/最小化的目标，等待已安排的逐窗观察确认；其余窗口继续提交。若提交过程中才发生同类变化，只允许一次过滤后的重试。替换 HWND、失去标记、权限/尺寸或其他移动错误仍拒绝，不据此放宽恢复身份规则。

最后一窗关闭后清理其恢复记录，空画布保持相机、工作区和运行状态；最小化最后一窗则保留该窗世界位置。两种情况下新开的可用普通窗口均经现有稳定等待与自动接入流程加入，无需打开主面板。用户手动关闭自动接入时仍尊重该选项。

## 证据和剩余范围

- 修复前：329/331 模型通过，新增两个最小化场景失败；99/102 原生通过，新增异步消息、快照刷新前关闭、真实增量最小化事件链均失败。该记录保留为回归证据，不归因于设备驱动。
- 修复后：332 模型、24 文件、102 原生检查，以及透明 UI 和完整原生总览检查通过。19 组隔离路由补双指右键等价序列；3 组隐藏接收器检查进入默认 CI。
- 原生生命周期夹具只使用自有透明窗口：模拟最小化先于目录刷新、实际 WinEvent 增量、保持最小化时平移、恢复、最小化后关闭、最后一窗关闭后新窗稳定接入；检查世界位置、相机和前台。另一检查在多窗/最后一窗销毁但快照仍旧时发起平移，验证不暂停。
- 真实触控板两轴/斜向、双指右键、应用点击及自然最小化/关闭后自动接入仍需新包复验。初始已最小化窗口仍不自动纳入；总览直接选择最小化条目恢复、最大化/全屏完整逐窗语义、更多设备及性能/发布矩阵继续列入 T11–T13。
- 源码和远端记录只保留合成夹具、代码和匿名计数；本地窗口身份、用户画面、输入轨迹、设置和恢复文件不上传。
