# 边缘加速、输入通知与诊断窗口

2026-10-24 用户反馈：触控导航和网易 UU 远控准星体验正常；边缘推进希望由低速逐渐加速；启动接管仍偶发失效，保存导航设置可恢复。随后一次复验启动正常，但输入状态窗口短暂出现后主面板无法点击并响系统提示音。

## 边缘推进

只有鼠标位于真正外缘、持续收到向外相对输入时，才推进相机。默认从 120 画布像素/秒开始，用 1.2 秒线性加速到 1800 像素/秒上限；设置中的指针倍率同时缩放这两个速度。窗口位移取决于持续推动的时间，不再取决于每个鼠标包移动了多少单位。

按时间积分，1ms/8ms/16ms 采样在相同持续时长得到相同距离；同一毫秒的额外包不虚构时间。每轴独立加速，角落可沿两轴移动；相邻显示器接缝仍可正常穿行。停止输入不生成后续位移，没有悬停自动滚动或惯性。零位移、反向、离开边缘、输入间隔超过 100ms、暂停/菜单/配置或系统边界均中断并重新从低速开始；不补偿停顿期间的距离。已接受输入仍由原有按帧调度消费，不改为在输入回调里移动窗口。

仅适用于相对输入的外缘推进。已通过用户复验的准星相对/绝对/普通消息路径和显式触控导航保持各自语义，不使用这条边缘加速曲线。实体设备下的加速手感仍需新版试用。

## 成功投递不等于已消费

此前修复了初始 UI 投递异常，但尚有另一条路径：回调成功启动计时器后，启动/恢复代码又将计时器停止，而 worker 合并标志仍等待 Drain。队列无法消费，新通知也不再投递；设置结束时 Drain 才能解除。新增隔离回归先复现此问题，同时复现新画布会话继承此前自动导航暂停状态；修复前 12/14 通过，两条新检查失败，保留失败记录。

现在 UI 回调确认“已送达”，只释放投递合并位，待消费标记仍保留。若计时器后来被停掉，输入线程在原有 100ms 看门狗上可再投递一次；旧回调尚未执行时不追加投递，避免 UI 挂起时堆积回调。Drain 才确认队列已消费。此路径不依赖新输入、设置窗口或周期重建钩子。

真正开始新的输入会话时恢复自动导航资格；同一会话内 Esc 仍维持原来的暂停规则，不立即重新进入。运行信息新增通知待消费状态、UI 泵启停与送达次数，均为内存内匿名计数，不记录鼠标轨迹或窗口身份。这两条复现不证明用户间歇故障只有这些原因，后续自然启动仍待观察。

## 持续可用的输入状态窗口

原诊断使用模态窗口，既有夹具很快关闭，未覆盖置顶主面板和自动收起周期下的使用。用户反馈揭示它可能消失在后方而仍阻止父窗体输入。现改为由主面板拥有的非模态窗口，继承置顶属性，提供“复制报告”和“关闭”，Esc 也可关闭；重复打开复用一个窗口并更新快照，不禁用主面板，不设短暂自动关闭。

托盘入口继续保留打开面板之前的快照，设备诊断与更多菜单也使用相同窗口。主面板自动收起会保护仍可见的自有窗口，主程序退出时释放报告窗口。“复制报告”只在用户点击时写入剪贴板；自动检查仅核验按钮和可选文本，不覆盖用户剪贴板。

## 验证边界

新增模型检查加速上下限、距离/采样率无关、暂停/反向/离边、接缝及角落独立轴。隔离 worker 覆盖成功投递后的停泵重试、回调合并与消费、新会话重入和边缘真实路由，使用合成平台，不安装钩子或接管真实输入。UI 检查用全透明不激活的自有窗口，保持报告至少 500ms，主动调用收起规则，验证持续可见、继承置顶、父窗口可操作、可选取/复制入口、复用和关闭。

实际边缘加速手感和更长时间的自然启动稳定性继续人工验收。用户已反馈触控导航、UU 准星正常，这是相应自然操作证据，不等于所有远控或触控驱动的兼容矩阵都完成。
