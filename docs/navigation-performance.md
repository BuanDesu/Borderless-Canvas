# 导航空闲与展示刷新

2026-10-27，首轮本地优化。范围是导航回调、空闲调度和诊断展示；未更改恢复协议或接管策略。

## 行为

`NavigationFrame` 继续消费输入、推进相机和手势。只有会话状态、消息、待确认状态、管理数量、活动窗口或总览工作状态变化时才调用完整刷新；单纯相机变化只更新导航展示并通知现有订阅者。无变化帧跳过候选生成、自动接入扫描、便签菜单目标计算、提示测量、预览失效和状态通知。保留候选列表的 `SequenceEqual` 与托盘缓存，状态文字变化时才显式测量布局；管理数量直接读取，避免为了计数分配 ID 数组。

16ms 导航计时器只为待处理位移、滚轮静默结束和相机过渡运行。按住但没有移动的手势保留起点，后续输入通过原有 owner HWND 通知重新唤醒。UI 使用独立 250ms 健康检查发送心跳，并为未消费通知提供兜底；它不会确认通知已消费。输入 worker 的 100ms 通知合并/重试、触控接收器维护和 1800ms 超时继续执行。位置确认仍由独立 40ms 计时器完成，HUD 使用独立的约 900ms 到期计时器。

`UpdateLiveMap` 始终先调用管理会话的观察路径。因此关闭、最小化、前台跟随、自动接入与恢复核验不受诊断页可见性影响。只读地图在显示时才同步展示模型；目录列表在显示且内容/过滤条件变化时才重建。隐藏、最小化或切到其他子页时保留最新快照，恢复显示时补齐；内容未变时保留列表行和选择。

## 合成测量

改动前先保存三轮 `.local/performance/before-*.json`。之后用相同最终测量夹具重建 `5fc9b8c` 的两个原始 App 源文件，补测包含隔离输入 worker 的前后各三轮；其他库共用当前构建，其中 worker 的维护代码仅提取为共享方法，生产行为不变。旧源文件和独立构建项目仅留在忽略的 `.local/performance/baseline/`，未改动当前源码以切换版本。

下面是后一次配对测量的中位数。批次场景先预热 50 次，再同步调用 1000 次；候选为合成数据，管理会话为空，不移动任何真实窗口。空闲场景各运行约 3 秒，使用真实消息泵和隔离 worker，不安装全局钩子、不注册原生快捷键、不枚举或采集用户桌面。触控工具条不显示，worker 使用合成平台。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 256 候选，无变化导航回调，1000 次耗时 | 2266.71ms | 0.70ms |
| 同批次 UI 线程分配 | 61,833,984B | 0B |
| 256 项隐藏目录，1000 次展示调用耗时 | 267.44ms | 0.030ms |
| 同批次 UI 线程分配 | 323,976,024B | 0B |
| 桌面空闲，3 秒导航计时器回调 | 93 次 | 1 次初始化回调 |
| 触控空闲，3 秒导航计时器回调 | 95 次 | 1 次初始化回调 |
| 两种空闲场景的完整展示刷新 | 分别 93 / 95 次 | 均 0 次 |
| 桌面空闲 UI 线程分配率 | 161,554B/s | 4,330B/s |
| 触控空闲 UI 线程分配率 | 165,220B/s | 4,160B/s |
| 桌面空闲进程 CPU 时间，约 3 秒 | 453.13ms | 15.63ms |
| 触控空闲进程 CPU 时间，约 3 秒 | 156.25ms | 31.25ms |

优化后两种空闲场景仍各执行约 11 次 UI 健康检查。CPU 是进程累计处理器时间，包含夹具消息泵和 worker，量化步长约 15.625ms；三轮桌面前/后范围为 421.88–656.25 / 0–62.50ms，触控为 109.38–281.25 / 31.25–62.50ms。CPU 噪声较大，应优先看工作次数和分配量。计数为 0 的样本低于计数分辨率，不能称为零 CPU。

这里的 0B 只指批次中当前 UI 线程的托管分配；空闲分配率包含 `DoEvents` 循环开销，不含 worker 线程分配。无变化回调和隐藏目录的巨大差值来自跳过整个展示路径，不代表实际输入处理、移动 256 个原生窗口或 GPU 呈现同幅提速。这些时间均不是实际屏幕呈现延迟。

## 验证及限制

- Release 构建：0 警告、0 错误。
- Core：338/338 模型检查；存储、启动器和包校验；23/23 隔离 worker 检查、5/5 隐藏接收器检查通过。
- Ui：隐藏 UI 与合成场景通过。新增回归覆盖无变化不刷新、隐藏/最小化/恢复显示及选择保留、嵌套页补刷新、桌面/触控空闲后首次输入、静止接触与持续手势、结束历史、读取期间通知重试、真实看门狗、相机/HUD 到期、总览请求资格刷新和独立位置确认/关闭核验。隐藏接收器检查还覆盖暂停、重启和重启后的首条滚动。
- 原有管道失败在沙箱内复现为客户端 `UnauthorizedAccessException`，服务端仍停留在等待连接。同一合成管道夹具及完整 Ui 层在普通权限环境通过；未改变管道产品代码、断言或超时。
- 共享真实看门狗维护方法后，旧隐藏接收器测试暴露出累计推进模拟时钟却不提供 UI 心跳的问题；补充模拟健康 UI 的心跳，保留全部接收器断言，并独立验证无心跳时必须超时退出。

本轮没有启动生产管理器接管用户窗口，也没有执行物理触控板、远控、多屏、真实应用移动或长期资源验收。后续候选保持独立：增量窗口查询按批复用虚拟桌面查询、恢复记录按 ID 索引、同步逐窗恢复可能阻塞 UI、总览搜索框方向键与选窗冲突。
