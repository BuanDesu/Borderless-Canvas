# 启动唤醒、远控准星与待恢复状态

2026-10-23。用户报告：首次启动可能让 Ctrl+滚轮等操作落入 Windows，打开导航设置并保存后正常；本地准星持续移动和退出正常，远控鼠标移动仍会退出；启动偶尔需要先处理旧恢复记录。

## 启动缺陷的复现与修正

输入通知通过 `wakePending` 合并。旧实现首次投递遇到尚不可用的 UI 句柄时，异常被忽略，合并位却保持“已投递”；后续状态和输入无法再唤醒 UI。关闭设置会调用 `Drain()`，解除合并位，所以可能表现为“保存设置后恢复”。管理器从恢复页启动时，画布子控件也可能尚未创建 HWND，旧入口会直接丢弃通知。

隔离 worker 用尚未就绪的 UI 回调先复现失败：路由已接受输入，但 UI 收不到通知，必须显式 Drain 才恢复。修正后投递失败释放合并位，保留待通知状态，并由输入线程定时重试；正常成功投递继续合并，不提高原生移动帧率。App 将通知投递给已存在的主窗体，而非要求画布子页已有句柄。

新增 UI 夹具隐藏并销毁自己的画布子句柄，保留主窗体句柄，验证后台通知能抵达；没有打开设置、接管真实窗口或限制鼠标。首次失败、UI 随后就绪但没有新输入的重试也进入默认 CI。该复现证明并修正了一条缺陷路径，不代替用户桌面复验。

## 准星输入适配

模式入口和退出仍为 Ctrl+Alt+C / Esc，单击保持。根据实际输入自动选择：

| 输入 | 处理 |
| --- | --- |
| 原生相对 Raw Input | 保留原有相对位移、中心单点限制，供本地键鼠使用 |
| 绝对 Raw Input | 读取 0–65535 归一化坐标，按主屏或虚拟桌面标志映射，连续位置之差作为视窗位移 |
| 只有普通鼠标移动 | 不因缺少 Raw Input 而退出；转为普通坐标兼容，拦截移动，按连续位置变化移动镜头，必要时保持中心光标 |

坐标依据微软 [RAWMOUSE 说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse)。首次采样、设备或映射区域变化、长间隔和大跨度跳变只建立基线；重复位置不移动。输入源切换重新建立基线，避免同一事件重复累计。普通坐标兼容使用当前显示器范围，保留进入前的鼠标位置和限制，并在退出时恢复；主路径仍用单点限制。

“更多 → 运行信息”新增“准星输入”，显示当前相对、绝对坐标或普通坐标兼容路径，供实际远控复验定位。没有记录或上传鼠标轨迹、设备标识、窗口内容和远控账户。

仅发送有限客户端绝对坐标、且不响应服务端居中的远控，无法由服务端软件单独保证相对输入那样的无限连续移动；需要远控工具的相对鼠标/游戏输入支持。不同工具还可能合并、注入或重定位事件，当前仅协议与隔离 worker 回归通过，不能据此宣称所有工具都已实测。外部程序更改鼠标限制、失焦、菜单、暂停、系统切换或看门狗仍保留退出保护。

## 待恢复不是输入已启动

旧会话记录、被其他实例占用或损坏的恢复文件会阻止重新接管。主面板显示“待恢复”，主动作改为“恢复”（辅助名称“恢复窗口”），引导到恢复中心；此时不启用画布输入。完成独立恢复、确认日志已空后恢复“开始”，仍等待用户点击，不自动接管。损坏或待恢复日志不自动清空，保留原有身份、标记和报告核验。

当前运行中的画布本来就持有恢复日志；诊断文件租约错误不会撤销正在运行的输入资格。明确暂停或退出仍按原流程恢复窗口。

## 验证范围

Release：304 模型、24 文件、87 原生（含 11 组隔离 worker），以及 UI/完整原生总览检查通过。新增模型覆盖归一化/负坐标、多设备和跳变基线、重复位置；原生解析覆盖 x86/x64 绝对样本和标志。隔离 worker 复用生产路由，验证启动失败重试、绝对输入、普通消息降级、输入源交接与退出恢复。独立恢复子进程检查补充待恢复主动作和完成后保持暂停。

自动检查不锁住用户光标、不启动远控、不安装真实快捷方式入口，不修改用户恢复文件。实际启动无需设置往返、具体远控工具的准星持续移动和设备组合继续人工验收。
