# 验收与验证

## 当前自动检查

执行 `scripts/check.ps1` 会先构建整个解决方案，再运行 81 项模型/策略检查和 6 项真实恢复日志文件检查。文件检查也进入默认 Windows CI，不要求交互桌面。任一失败返回非零退出码。`dotnet test` 不代替本项目的 Checks 程序。

| 检查 | 对应需求 | 验证内容 |
| --- | --- | --- |
| Pan preserves layout | FR-01/02 | 多次跨正负坐标平移后，世界布局与相对位移不变 |
| Focus preserves layout | FR-03 | 远处窗口中心映射到视口中心，窗口世界位置不变 |
| Home and back | FR-04 | 返回原点/上一视角不收拢窗口 |
| Overview is spatial | FR-05 | 统一比例、空间顺序、距离和负坐标逆变换正确 |
| Dynamic bookmarks | FR-06 | 超过九个书签；删除书签不会让其他 ID 指错位置 |
| Invalid geometry | NFR-04 | 非数、非正尺寸、不可用地图范围在投影前被拒绝 |
| Missing targets | FR-03/06 | 已关闭或不存在的目标不会改变相机和历史 |

`scripts/check.ps1 -SmokeUi` 以透明、无任务栏项且不激活的方式初始化桌面壳，绘制模型、窗口、显示器、地图和恢复五页 PNG 后关闭。JSON 保存计数和监听状态，不写标题；窗口页和地图图片可能包含标题，仅本地保留。它不证明真实接管、全局手势或 DPI 兼容已经验收。

`-NativeChecks` 额外运行 33 项原生检查，覆盖发现、显示器、事件、恢复和离屏对照。仅改变项目自身测试窗口，不操纵用户应用。完整范围见[窗口发现](window-discovery.md)、[显示器](display-coordinates.md)、[事件](window-lifecycle.md)、[恢复](recovery.md)及[离屏 ADR](adr/0002-bounded-offscreen-parking.md)。

T02 新增 12 项模型检查覆盖负原点、四边任务栏、往返、原生尺寸、取整、整数边界、溢出、无效几何与拓扑、100% 基线判定、不可变快照和视口尺寸更新；其中负坐标显示器和 100% DPI 不等于已有相应硬件实测。

## 真实桌面验收场景（后续执行）

| 编号 | 场景与操作 | 通过条件 |
| --- | --- | --- |
| AT-01 | 单屏工作区内放置 4 个窗口，连续平移到负坐标和远处 | 无分页，窗口原生尺寸和相对位置稳定，背景/任务栏固定 |
| AT-02 | 把窗口放在原点外，聚焦它，再返回原点 | 相机移动，窗口不被拉回原点；布局未改变 |
| AT-03 | 打开地图，按方向键选择、搜索，最后 Esc | 空间布局不重排，工作相机与焦点保持原状 |
| AT-04 | 地图选定远处窗口并确认；随后返回上一视角 | 相机到达目标、可输入，返回位置正确 |
| AT-05 | 从任务栏激活离屏窗口；另一个应用激活关联对话框 | 目标可被找回，无长期不可操作的模态框 |
| AT-06 | 打开地图后关闭目标；拒绝预览的窗口进入地图 | 已关闭目标安全移除，预览失败以占位符降级，其他项可选 |
| AT-07 | 保存 128 个标签，重名、重命名、删除并重启 | 无固定槽位上限；ID 不漂移，布局恢复可解释 |
| AT-08 | 一次拖动后返回上一视角；连续滚轮后返回 | 一次手势合并成一次导航历史，不按每帧后退 |
| AT-09 | 接管后正常退出、强制结束、重启恢复入口 | 仍存在的窗口恢复到可操作区域，不操作复用句柄对应的新窗口 |
| AT-10 | 接管过程中部分窗口拒绝移动或激活 | 不阻塞整个桌面；错误可见且可恢复，逻辑与实际状态可协调 |
| AT-11 | 最大化、全屏、最小化、置顶、弹窗和输入法 | 按需求中的规则退出/暂停画布管理，关联窗口不丢失 |
| AT-12 | 两屏不同 DPI，拔插副屏、更换主屏、休眠恢复 | 无跨屏漏出或坐标漂移，失联窗口可恢复 |

## 性能验证计划

M2 起记录 OS build、CPU/GPU、分辨率、刷新率、DPI、窗口数量及测量工具。单屏 1920×1080 / 60 Hz / 10 个普通窗口作为第一组基线；目标输入到可见运动的 P95 不超过 50ms，平移调度按刷新率合并。该数值是开发目标，尚无实测结果，不代表对任意应用的性能保证。

30 个及更多窗口、动态内容窗口、预览开关、离屏窗口增长都单独测量。空闲时采用事件驱动，不持续全量轮询或绘制；CPU/GPU/内存占用先建实测基线，再制定限制。
