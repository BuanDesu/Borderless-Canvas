# 总览入口与原生预览负载

跟踪 #12 / #41。此记录只证明总览渲染和原生缩略图这一部分的成本；T12 的真实输入到可见运动、GPU 占用、动态第三方应用及可撤销区域整理仍未完成。

## 重现方式

在交互 Windows 桌面运行：

```powershell
.\scripts\measure-overview.ps1
# 或选择一个尚不存在的报告路径
.\scripts\measure-overview.ps1 -OutputPath .local\overview-load\run.json
```

脚本构建 Release，记录源码提交和已跟踪文件修改状态，再运行 `--overview-benchmark`。默认报告位于 ignored `artifacts/overview-load/`。它只创建自己的非激活工具窗口，不注册全局导航、不注入输入、不读取桌面或壁纸，不移动其他应用。工具窗口样式使其不会被另一个画布实例作为普通新窗口接入。结束后关闭全部自有窗口、时钟及原生关系。

矩阵为 1/10/30/60 个原生源窗口，预览开/关，0/约 50% 物理离屏，各三次，共 48 个样本。世界坐标布局和三个工作区固定；离屏只改变自有源窗口的物理位置。背景是程序生成的纯色。地图和工作区使用生产场景与 `OverviewPreviewSession`、真实 `DwmOverviewPreviewPort`；包括原生注册、裁剪、透明度更新和释放。每个关系仍需验证身份、可见性、最小化、cloak 及当前桌面。

首次 WPF 预热独立记录；各组创建及初次绘制在采样前完成。整组采样共用一个 WinForms 消息循环，以免每关一个测量宿主就释放其他源窗口。报告只含数值和源码信息，不含窗口标题、HWND/PID、像素、壁纸路径或账户身份。

## 从基线得到的改动

原先每个预览关系的两次完整核验各自创建一个 `IVirtualDesktopManager` COM 查询对象。一个窗口同时出现在地图和多个工作区时，这项开销会重复。

现在 `IOverviewPreviewPort.BeginBatch` 为一次同步提供同步作用域。原生适配器在首次需要注册时才创建查询服务，整批复用，结束立即释放；已有关系、禁用及动画路径不创建该服务。嵌套作用域复用外层服务，直接调用 Create 也有局部作用域。没有缓存身份、可见性或虚拟桌面查询结果，每个关系的两次完整核验、实例标记及后续身份保护仍保留。

模型检查覆盖整批边界、动画不进入查询作用域、异常、非法输入及重入关闭。原生检查覆盖同批内失效身份、隐藏后拒绝、显示后恢复、嵌套后继续及源销毁。首次完整检查还发现夹具依赖默认快捷键空闲、默认窗口位置的假设：现改为实际注册空闲测试组合，并固定遮挡窗口的位置、确认相交与就绪；不降低断言或延长等待期限。

## 本机开发态观察

OS build 26200，1920×1080 场景、144 DPI、WPF tier 2。下表只使用物理离屏数为零且启用预览的每组三次算术均值。前后都使用同一负载夹具；不是随机化实验，也没有消除 GC、系统调度和其他进程的影响。

| 源窗口 | 原生关系 | 同步前 / 后（ms） | 夹具入口至首回调前 / 后（ms） |
| --- | --- | --- | --- |
| 1 | 2 | 8.6 / 6.4 | 109.1 / 111.5 |
| 10 | 24 | 42.5 / 8.8 | 128.0 / 110.2 |
| 30 | 66 | 112.7 / 19.0 | 237.5 / 132.9 |
| 60 | 100 | 163.1 / 28.1 | 281.7 / 120.9 |

多窗口同步开销有明显下降；单窗完整入口尚无改善证据。最后一次 48 样本的前台窗口未改变，注册/释放计数一致，但这不足以证明长期无泄漏。进程私有内存峰值约 380 MiB，包含 WPF/运行时/原生夹具；不是仅总览的额外内存。进程 CPU 时间不含 DWM/GPU 成本。

仍观察到约 30–40ms 的启用预览回调长间隔，其他组合也出现更长间隔。回调时刻不是屏幕呈现时刻；这些值不是帧率保证。夹具没有走键鼠钩子、真实画布移动、管理器隐藏、桌面采集、真实焦点图像缩放或任务栏路径，不能代替用户自然操作，也不能据此认定 NFR-03 的输入 P95 目标已达成。

## 生产入口计时

可选 `--motion-metrics` 增补 InputDispatchMs、UiQueueMs、HostHideMs、HostShowMs、SceneLayoutMs、PreviewLayoutMs、PreviewSyncMs 和 PreviewSyncCalls。桌面纹理上传单独记录 UploadMs。生产计时仍只写数值。

这些阶段有包含关系：HostShow 包含布局和初次预览，Prepare 包含场景布局与预览同步，Capture 包含上传，PreviewSync 是多次同步的累计值，不能直接相加。当 SceneReused 为 true，构造及准备字段描述最初打开，RequestToFirstCallback 描述本次反向请求。完整入口以输入捕获至首回调的单调时钟为准；该指标仍未证明首次可见画面的呈现延迟。

后续需继续测量主观顿挫对应的实际呈现、不同设备和多屏、持续动态源、空闲占用及多轮打开关闭资源趋势。当前真实试用反馈继续在 #41 跟踪，不以此负载结果替代。
