# 完整总览的原生宿主适配

这是上一轮[原生宿主实验](live-overview-surface.md)的生产结构适配，仍需显式启用。默认启动保留 WinForms 顶层窗口，新路径使用真实 WPF 顶层窗口；两者复用同一个 `SpatialOverviewView`，地图、搜索、工作区和 CRT 内容不再分别实现。

## 使用与边界

试用包的 `Start.cmd` 继续启动默认路径。要验证新路径，先从托盘“退出并恢复窗口”，再双击 `Start-NativeOverview.cmd`；也可以运行：

```powershell
./BorderlessFlatWindow.App.exe --native-overview
```

它接入现有管理器、画布会话、全局快捷键、选窗和恢复流程。`--native-overview-solid` 可强制纯色降级。Windows 11 build 22621 起可请求系统 Desktop Acrylic；系统不支持或高对比度时使用纯色。接口成功仍不证明实际背景视觉符合要求，不修改系统透明度设置。

这里尚未将原生路径设为默认，也没有完成真实连续呈现、自然操作、混合 DPI 或全部兼容验收。工具画面中背景仍呈纯色。目标是保留空间关系并减少同步桌面读回，不能以降低总览功能或静态卡片列表替代需求。

## 结构与所有权

- `SpatialOverviewView` 是可直接放入 WPF 窗口的视图，负责布局、空间投影、搜索、工作区、输入命令和唯一 WPF 动画值。
- `SpatialOverviewScene` 是保留原 API 的薄 `ElementHost` 适配器。默认窗体继续使用它；重复释放不会再次访问已销毁的 ElementHost 内部对象。
- `IOverviewPresenter` 是管理器与具体宿主之间的边界。`FormOverviewPresenter` 包装已有窗体，`NativeOverviewPresenter` 使用 `SpatialOverviewWindow`。接口的 Handle、Visible、Closed 都对应实际显示的顶层窗口，没有隐藏或覆盖 Form 属性来伪装宿主。
- 空闲缓存继续保存一个尚未使用的 presenter，沿用完整输入快照、重入代号和单次转移。原生隐藏准备不激活、不绑定外部预览、不读取桌面；背景接口和布局可以提前准备。后续实际打开才重新提供、核验源并注册预览。启动时原生路径只预热共享视图，不创建旧 ElementHost 场景。

新路径的 `PreparePresentation` 不调用屏幕读回或焦点位图裁剪。它将现有地图及工作区切片绑定到实际 WPF HWND 的 DWM 预览；选中源只有在身份、位置和遮挡核验满足条件时才请求原生矩形过渡，否则淡入地图。它不会重新构造源窗口上方的叠加层。离屏内容仍可能停帧。

全局输入继续以会话编号隔离晚到事件，Shown/Activated 提供真实 HWND；原有资源管理器焦点回落兜底继续作用于这个 HWND。选窗确认立即关闭、交接相机与焦点。Tab 切换可以反向；到端点停止 Rendering 订阅，DWM 内容关系独立刷新。外部暂停或管理器取消会直接释放宿主。

工作区编辑使用以真实 HWND 为 owner 的 WinForms 模态框，期间保留模态深度和原生禁用检查；关闭前先释放场景事件、预览和菜单，再通知管理器完成，避免焦点/COM 回调重入旧会话。

## 验证

```powershell
./scripts/check.ps1 -Configuration Release -SmokeUi -NativeChecks -NativeOverviewChecks
```

本轮通过 309 项原有模型/存储/原生检查、默认 UI/场景检查，以及新增验证：

- 1920×1080、3440×1440、960×720，原生背景请求与强制纯色两组，共六个实际 presenter 样本。在真实 WinForms 消息循环中验证隐藏预热无激活/零预览、地图及工作区真实预览、往返及端点空闲后的重新反向、搜索空结果不确认、轮选确认、一次关闭与预览释放。
- 交互样式隐藏 WPF 宿主的三尺寸检查；取消准备后不显示、完成仅一次；重复 Dispose。
- 显式关闭动画时直接完整显示、零动画回调，切换关闭立即释放；系统动画关闭时也不把无回调误判为测试超时。
- 独立视图在合成 100% / 125% / 200% DPI 下的物理预览范围和 1600×1200 图像尺寸。它不是实际混合 DPI 显示器验收。
- 自有 WinForms 模态框中，仅向夹具自身子 HWND 投递 Tab / Esc 消息，验证实际模态消息循环切换控件、取消、宿主禁用与重新启用。它不覆盖硬件输入或全部输入法。
- 首次入口和后续反向分别记录时间；后续 Tab 不会覆盖首次请求，使入口字段错误变为 0。缺失计时写 null，不解释为零延迟。

真实管理器只接管自有 Probe，关闭自动接入。已观察实时地图与工作区背景、地图点选 Source、快捷键重开、Tab 返回；正常暂停后待恢复/armed 均为零。另一次打开工作区保存框后，桌面工具能读取该嵌入模态框却不能把输入定向到它，因此没有声称实际保存/取消的自然操作已通过。该次严格核对唯一源为自有 Probe 后结束测试管理器，独立恢复程序核验原位置与显示状态并清零；没有接管其他应用。

真实自有源的两次显示阶段约为 63.7 / 19.5ms、准备阶段约为 19.5 / 2.8ms；首个样本入口到首回调约 156.9ms。第二个样本的旧入口计时受上述覆盖问题影响，不引用其入口值。顺序、冷/热状态、源位置与工具操作都有影响，这不是与默认路径的随机对照，也不证明提速或屏幕实际呈现。两次焦点变换均因资格不满足而降级，不能据此验收真实窗口的缩小效果。

可选匿名指标保留 renderer、背景 HRESULT、尺寸、计数和阶段耗时，不包含窗口标题、输入内容、身份或桌面像素。原始本地状态、工具画面和报告不提交仓库。默认 CI 只编译这些桌面代码；原生宿主检查需显式在可交互桌面运行。

下一步仍需背景材质与连续过渡的实际呈现、自然快速连按、真实工作区编辑、多窗口/长期资源、跨进程遮挡与裁剪，以及多屏/DPI/特殊状态的完整验收；T11/T12 保持开放。
