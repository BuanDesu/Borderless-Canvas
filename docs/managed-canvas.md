# 真实画布管理（T06）

2026-10-18。首个真实接管入口位于“窗口画布”页。当前为单屏实验管理器，全局手势、独立总览与标签持久化尚未交付。

## 操作

1. 运行 `scripts/run.ps1`，勾选待管理普通窗口，点击“开始 / 恢复画布”。当前只开放有效 DPI 已知的单显示器；最大化、全屏和置顶不接管。选择在开始前重新核验，失效项不会被静默忽略。
2. 箭头按钮、地图内滚轮与 Shift＋滚轮改变工作相机。窗口尺寸与世界位置不变；地图卡片保持空间关系，虚线框代表视口。地图“适配全部”只调整地图显示比例。
3. 点击卡片先整体定位相机，确认真实位置后请求激活。Windows 拒绝激活时显示原因，仍可直接点击已定位窗口。此页 Home/Backspace 返回原点/上一视角；当前每次平移独立记录，T07 合并手势历史。
4. “暂停并恢复原位”或正常退出将窗口恢复到接管前位置。同一批窗口再次开始保留本次进程中的世界布局、相机与模型书签；换选择重新建立画布。布局跨重启持久化尚未实现。
5. 异常退出后通过恢复页或 `scripts/recover.ps1` 处理旧记录，具体命令见[恢复说明](recovery.md)。恢复失败保留记录，处理完后才允许新会话。

不要同时用 Probe Controller 的“停放/裁剪”操作已经由主程序管理的 Source；它是独立离屏实验，不共享管理会话。

## 平移与协调

`ManagedCanvasSession` 保存逻辑布局、原生观测、期望位置、停放状态和待激活目标。所有窗口先完成持久登记，所有位置先规划并验证，随后才提交移动。屏幕外使用[有界停放](adr/0002-bounded-offscreen-parking.md)，不把停放坐标反写成世界坐标。

同一 UI 线程内用 Begin/Defer/EndDeferWindowPos 提交组；跨线程使用逐窗异步 SetWindowPos。实测 DeferWindowPos 携带 ASYNCWINDOWPOS 返回错误 87，因此跨线程路径不依赖这一组合。组提交不承诺跨进程原子性；部分失败通过整组暂停恢复协调。不改变尺寸、Z 顺序、可见状态，也不在平移中请求激活。

预期中间矩形可接收乱序/合并移动回调，但不能作为外部布局编辑。位置有进展才延长 1500ms 确认期限，积压最多保留 128 个预期矩形；超时、意外位置或尺寸、关闭、失去身份/准入、最大化/置顶变化触发暂停恢复。可见稳定窗口的外部拖动/缩放会更新自己的世界矩形。普通有标题的关联弹窗（包括间接 owner 链）触发暂停，以免其 owner 留在屏幕外。

WinEvent 负责日常增量同步；40ms 验证计时器只在原生位置尚待确认时读取相应 HWND，确认结束即停止，不在空闲时全量轮询。候选列表内容变化才重建，避免子控件事件导致持续刷新和勾选失效。

前台事件发现目标处于停放状态时，整体定位相机到目标；Windows 在激活前自行搬回的物理中间位置不会改变世界布局。它复用任务栏/Alt+Tab 产生的前台事件路径；实际任务栏点击仍须单独验收。

显示配置/DPI 消息会暂停并恢复，重新读取配置后重建会话。恢复总会发送原始 placement，再检查目标线程响应，避免“当前位置看似原位，旧异步移动随后才执行”的竞态。卡住的目标保留日志供独立恢复重试。
