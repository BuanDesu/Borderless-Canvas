# 无桌面读回的原生总览宿主实验

状态：独立、显式启用的开发实验。普通启动仍使用现有总览；本实验不表示过渡流畅度已经验收，也不替换地图、搜索、工作区或输入会话。

## 验证的问题

现有入口会同步读取整屏背景，再上传背景和可用的焦点裁剪。这里验证另一条公开接口路径：非分层 WPF 顶层窗口承载控件，系统绘制背景材质，DWM 实时缩略图直接从源位置过渡到空间投影位置。实验完全没有调用桌面截图、焦点截图或位图上传路径。

- [DWM_SYSTEMBACKDROP_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type) 的 `DWMSBT_TRANSIENTWINDOW` 在 Windows 11 对应 Desktop Acrylic，最低支持 build 22621；系统可改变具体材质表现。
- [WPF 扩展玻璃框架](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/extend-glass-frame-into-a-wpf-application)说明透明 Window 背景、透明 HwndTarget 与 DWM 框架扩展的组合；实验不使用分层窗口。
- [DWM 缩略图](https://learn.microsoft.com/en-us/windows/win32/dwm/thumbnail-ovw)提供二维、持续的源/目标关系，可以更新目标矩形；这不是任务视图嵌入接口，也不提供 GPU 呈现时间。
- [WinForms/WPF 输入互操作](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/windows-forms-and-wpf-interoperability-input-architecture)使用 `EnableModelessKeyboardInterop`，以便从 WinForms 入口启动的 WPF 窗口接收正常输入。

`NativeOverviewBackdrop` 在调用前要求目标属于当前进程且是顶层窗口，旧系统返回不可用；设置、读取和扩展框架的 HRESULT 分别记录。高对比度、不支持或显式降级时使用可读的纯色背景。接口接受并不等于当前会话一定显示了透明或模糊效果，不更改系统设置。

## 实验边界与运行

在交互式 Windows 桌面上执行：

```powershell
./scripts/check.ps1 -Configuration Release -SmokeUi -NativeChecks -LiveSurfaceChecks
```

`-LiveSurfaceChecks` 独立于默认检查，运行原生背景请求及强制纯色降级两组实验。每组先运行三个正向/反向/再次正向的样本，另有一个在动画途中关闭的样本，之后再运行两个普通样本以观察延迟清理。报告写入全新的 `artifacts/live-surface/` 子目录。默认 CI 编译这些代码，但不执行需要交互桌面的实验。

编译后也可使用新的报告文件手动观察（Esc 退出；180 秒自动结束）：

```powershell
./src/BorderlessFlatWindow.App/bin/Release/net10.0-windows/BorderlessFlatWindow.App.exe --live-overview-lab artifacts/live-interactive.json --lab-interactive
```

追加 `--lab-solid` 强制纯色降级。报告已存在时拒绝覆盖。实验没有主面板、托盘、全局快捷键和恢复日志，不接管或移动外部应用；只创建三个自身进程的合成窗口，工具/置顶样式使其不成为运行中画布的普通自动接入候选。世界位置包含正、负和视口之外的坐标，使用现有统一比例 `OverviewProjection`，没有把卡片重排成网格。它尚未验证真实离屏应用的刷新行为。

首个源使用完整的实时缩略图，并不重建屏幕上覆盖它的其他窗口或叠加层。位置正确不能证明入场首帧与当前桌面像素一致；实验没有替代生产路径的前后身份、位置和遮挡核验。生产接入仍需为遮挡、裁剪和不可预览目标明确降级方式。

## 时钟、空闲与释放

WPF 的实际动画属性是位置的唯一进度来源。反向从读取到的当前值开始；回调只更新发生变化的目标矩形和透明度。到达端点后解除 Rendering 订阅，实时内容仍由 DWM 的源/目标关系更新，不需要空闲时反复提交相同属性。

自动样本在端点等待 180ms，断言没有新增回调或缩略图属性写入，再关闭；另一个样本在中途关闭，核对三项资源均释放、没有晚到回调。关闭停止全部定时器、解除静态事件、清除动画并释放全部预览。自动运行还要求来源和宿主显示前后保持原前台不变、实际宿主范围匹配工作区。

## 当前证据与限制

本机初轮两组各三个样本均成功：背景接口返回成功，实际创建/释放各三个预览，属性更新无失败，反向两次，原前台不变。加入端点空闲断言后两组均通过。每组首轮有 WPF 缓存初始化；后续版本观察到关闭后 USER 有时增加 1，因此额外记录即时计数和垃圾回收后的计数，不能把显式预览释放等同于全部平台资源已经回收。

扩展诊断中，普通样本的 USER 增量经回收归零；中途关闭样本还暂留 1，下一次普通样本回落 1。实验在关闭后保留 80ms 消息处理时间，并在测量阶段之外显式收集垃圾、处理延迟清理，分别保留前后数字。末轮要求 GDI/USER 回到首轮初始化后的基线。这只用于开发实验，不在产品总览中强制垃圾回收，也不据此宣称长期资源稳定或特定平台对象已经定位。

最终版本的原生与纯色两组各六个样本通过上述断言，末轮回到初始化后的基线。原有 309 项模型/存储/原生检查以及 UI/场景检查通过。停止端点回调后的交互复查仍能看到源内容持续变化，Tab / Shift+Tab 可重新启动过渡；该次观察期间仅产生 140 次动画回调、345 次属性写入，三项预览均释放，无超时。这些计数用于验证空闲工作已停止，不能当作帧率。

初轮端点检查版本的原生路径：Show 为约 134 / 55 / 65ms，入口至首回调约 154 / 57 / 67ms。构造、显示、初始化和原生预览的工作仍存在；不同夹具和不同冷/热状态下不能拿这些数字与生产入口直接作速度对照。Rendering 回调间隔也不是屏幕呈现间隔或完整输入延迟。

桌面工具已观察到三个真实缩略图的合成内容持续变化，文本输入正常，Tab / Shift+Tab 可往返，Esc 后四个窗口均消失。此实验自身使用 WPF 消息循环；不能仅凭这次输入成功声称已验证生产 WinForms 循环中的完整互操作。工具捕获中的背景表现为纯色，无法确认当前桌面的实际 Acrylic 模糊效果；因此没有以 HRESULT 成功宣称已取得预期毛玻璃视觉。一次用通用运行时启动的交互观察因工具选择超时而由看门狗结束，不计作交互验收；之后项目 EXE 的观察完成并正常退出。

报告只含尺寸、计数、布尔值、HRESULT 和耗时，不保存桌面像素、窗口/进程标识、输入内容或标题。工具画面、原始本地报告及运行状态不提交仓库。

下一步需要在保持完整空间地图、工作区和已验收的 Tab 会话语义的前提下，建立明确的视图/宿主接口，验证背景可控性、焦点交接、多屏/DPI、输入及连续呈现，再决定是否接入生产路径。不能用隐藏或覆盖 Form 的 Handle/Visible 属性来伪装 WPF 宿主，也不能仅凭此实验切换默认实现。
