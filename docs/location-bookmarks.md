# 位置标签与本地存储（T10）

2026-10-19 反馈改进：当前操作以[自动导航、多屏与工作区说明](interaction-refresh.md)为准。本文保留早期阶段的实现和验证证据；其中单屏限制、手动模式、独立标签页及默认关闭自动接入的描述属于旧版。

2026-10-18。标签是共享画布上的命名相机位置，不是隔离桌面或窗口分组。它们不隐藏其他窗口，也不把远处窗口搬到当前位置。

## 操作

1. 从窗口画布的“位置标签…”按钮或“位置标签”页面进入。输入名称后“保存当前位置”，保存当前相机左上角的世界坐标；名称两端空白会去除，允许重名。
2. 列表显示名称、坐标和稳定 ID 的前 8 位。名称相同的标签可用位置和 ID 区分；ID 不使用名称、列表索引或 1–9 槽位。
3. 选中一项，编辑名称后“重命名”；ID 和坐标保持不变。“删除标签”只删除该书签，不移动或删除窗口，也不改变相机及导航历史。
4. 搜索按名称匹配，忽略大小写，不改变存储顺序或工作相机；空结果禁用重命名、删除和跳转。自动选择搜索结果时，名称输入框同步到所选项。
5. 开始画布管理后，选中标签点击“跳转”，或在列表/搜索框按 Enter、双击列表项。通过真实管理会话整体平移相机，再次“上一视角”可回到跳转前。未开始或已暂停时禁用跳转，仍可管理标签。

进入标签编辑会结束当前导航手势并退出全局导航模式；用户仍可显式重新进入全局导航改变相机，再保存另一个位置。切换到标签页不移动窗口。

名称最多 256 个 UTF-16 字符单元，不允许控制字符。标签数量不设固定槽位上限；当前 JSON 文件读写上限为 16 MiB，实际容量受内存、磁盘与界面资源限制。已经检查至少 256 个标签。

## 持久化与恢复

默认文件为 `%LOCALAPPDATA%\BorderlessFlatWindow\bookmarks.json`。每次新增、改名和删除先成功保存，再更新内存/界面；失败不会显示未保存的数据为已完成。关闭和重启读取同一文件，保留 ID、名称、坐标及顺序。

可指定独立试用文件，不影响默认标签库或恢复日志：

```powershell
dotnet run --project src/BorderlessFlatWindow.App --configuration Release -- `
  --bookmarks C:\path\to\bookmarks.json --journal C:\path\to\recovery.json
```

JSON 包含 `Version: 1`、非负 `Revision`，以及每项的 `Id`、`Name`、`X`、`Y`。标签只保存用户输入的名称和世界坐标，不保存窗口句柄、应用标题或进程信息。

- 写入使用同目录唯一临时文件、WriteThrough/Flush 和原子替换；失败清理临时文件并保留旧文件。
- `.lock` 是进程持有的独占文件租约；文件本身留在目录不表示仍被占用。另一实例不能同时写标签，但主程序仍可打开和使用其他功能；释放租约后可“重新读取标签”。
- 读取和保存时校验内容摘要，避免用过期内存覆盖外部修改。拒绝未知版本、缺字段、重复/空 ID、非法名称、非有限坐标、负修订号和超大 JSON，整份验证成功才替换集合。
- 读取失败保留已经加载的标签，禁用写入，提供“重新读取标签”；损坏/未知版本文件另提供“备份原文件并新建”。该操作先复制原文件到同目录的唯一 `.backup-时间-GUID.json`，再原子写入空标签库；备份或写入失败不清空内存和原文件。状态文本可复制备份路径。
- 超大文件不会反序列化，摘要与备份按流处理。很大的文件仍可能需要等待磁盘 I/O；当前存储操作在 UI 线程上，未做异步大型库优化。

恢复日志与标签文件使用独立格式、路径和租约。标签损坏不授权恢复或移动任何窗口，也不阻止使用窗口画布。

## 模型与边界

`BookmarkCollection` 保存稳定条目并提供整份替换验证；`BookmarkLibrary` 通过存储端口执行保存后发布、只读降级和备份重建。当前管理工作区共享同一集合，重新开始选择、暂停恢复及显示配置重建不会丢掉标签。

`ManagedCanvasSession.GoToBookmark` 查找稳定 ID 后走正常的 `Navigate`，遵守暂停、总览冻结、写前登记和原生移动确认规则。它不调用只读示例模型来假装完成桌面跳转。

标签保存世界坐标，不自动恢复上一次运行的窗口世界布局，也不绑定应用。正常退出仍先恢复窗口原始位置；下一次接管以当前窗口位置建立布局，原标签坐标仍保留。不同 DPI/工作区下不自动缩放标签坐标。多屏接管限制继续按管理会话规则执行。
