# 触控板双指右键与桌面菜单交接

2026-10-25。核对并直接启动正式构建 `2c212b3` 后，用户确认真实画布双轴移动已恢复；但桌面空白处的触控板双指轻点需要多次才弹出右键菜单，顶部触控条仍然存在。接收层命中修正有效，菜单交接尚未通过。

## 前次透明交接尝试（实体复验未通过）

上一版点击后约 100ms 恢复接收，桌面移入还会请求接收层焦点。双指轻点后的轻微指针移动可能因此在 Windows 异步打开菜单时再次激活接收层。

现在仅在进入触控模式或用户点击提示条标题时请求焦点，指针在桌面移动不再自动激活接收层。右键按下和抬起均透传，并把该次点击的透明交接期保留至少 500ms；其他按钮仍为 100ms。后续按钮不会缩短已经存在的交接期，按住期间和系统菜单打开时均不重新接收。菜单结束后恢复原滚动接收路径。

保留真实客户端命中、进入时的焦点请求、纵横轴精度与 Shift/Ctrl 语义，不恢复左键拖动画布，也不向桌面重放双指轻点。

## 验证边界

新增隐藏自有接收器检查先复现点击后过早重新接收，再验证延迟菜单、菜单期间持续穿透、关闭后恢复和后续水平小增量。它进入默认 CI，不安装输入钩子、不注入桌面点击。Release 332 模型、24 文件、104 原生检查，以及 UI/完整原生总览通过，构建无警告或错误。

用户的正式版两轴移动结果作为已通过证据保留；本轮桌面双指右键、应用点击与菜单关闭后的连续滚动仍需实体复验，不能用隐藏消息检查代替菜单实际行为。

## 后续实体反馈与诊断

用户复验 `de8ee03` 后反馈桌面右键仍需多次轻点，故上面的透明交接与取消移入激活不足以证明问题解决。双轴恢复的证据保留，右键目标投递继续排查。

另外已独立复现退出通知时序问题：输入线程先唤醒界面、后发布非活动状态，界面可能仍按旧的 Touch 状态处理退出；触控退出也未写入最近退出原因。修正为先发布非活动状态，再通知退出，并保留触控退出原因。新增默认隔离线程检查由失败变为通过；这项时序错误尚未被确定为实体右键症状的原因。

输入状态增加实际构建、输入线程模式与触控界面状态的分别显示，以及右键钩子按下/抬起、接收窗口按钮/菜单和意外按钮计数。只统计数量与固定状态，不记录输入位置或窗口内容。诊断变更通过默认检查：332 模型、24 文件、20 组隔离输入线程、5 组隐藏接收器；当前实体右键仍未通过，不以这些检查替代现场失败后的状态数据。

## 桌面成对交接

失败后报告未显示钩子失效或积压，最近导航消息仍是触控状态，但旧版没有右键投递计数。后续对桌面轻点采用成对交接：仅在工作区内、没有菜单或修饰键、光标下实际是 Shell 桌面时暂存右键按下；抬起后让接收层穿透，在输入线程上重新核验相同 Shell 进程、桌面根窗口和子目标、指针释放位置及画布状态，再交还一对带自有标记的右键事件。该标记绕过再次拦截，不移动光标，也不退出触控模式。

应用、任务栏和其他目标不进入交接。菜单或目标改变、左键组合、指针移离、暂停/退出会取消待交接轻点，已经截留的抬起仍只配平一次。Shell 进程通过 [GetShellWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getshellwindow) 核对；[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) 返回成功插入的数量，计数代表系统接受输入，不代表菜单视觉验收已经完成。

新增两组隔离输入线程检查先失败再通过，覆盖单次交接、应用透传、菜单/目标/左键组合/暂停取消，以及左键组合结束后的下一次正常轻点。另以自有小窗口核验实际 `WindowFromPoint`：接收层开启时命中接收层，透明时精确露出自有下层，重新接收和销毁不改变前台；不移动真实光标或注入测试点击。

完整 Release 回归通过：332 模型、24 文件、108 原生，以及 UI/完整原生总览；默认 CI 包含 22 组隔离输入线程和 5 组隐藏接收器。实体桌面双指右键与菜单后连续滚动仍待本次包复验。
